# Java задание Автомобили

Пока подготовлена только структура проекта на Java 17+. Бизнес-логика,
консольное меню и работа с файлами будут добавляться отдельными шагами.

## Модули и зависимости

Стрелка означает зависимость исходного кода:

```text
domain         → только стандартная java.base
application    → domain
infrastructure → application, domain
presentation   → application, domain
bootstrap      → application, domain, infrastructure, presentation
```

| Модуль | Ответственность |
| --- | --- |
| `domain` | Модель автомобиля и её инварианты |
| `application` | Сценарии работы с каталогом и интерфейсы необходимых внешних операций |
| `infrastructure` | Реализация внешних операций, например чтение автомобилей из файла |
| `presentation` | Консольное меню, ввод и представление результатов |
| `bootstrap` | Точка входа и создание объектов с передачей зависимостей |

`presentation` не зависит от `infrastructure`. Консоль вызывает сценарий
прикладного слоя, а тот обращается к интерфейсу, определённому внутри
`application`. Реализация этого интерфейса находится в `infrastructure`.
`bootstrap` соединяет реализацию со сценарием через конструктор.
Это инверсия зависимости: прикладной слой не знает о файловом адаптере.

## Ограничения слоёв

Каждый модуль собирается в отдельный JAR. Зависимости сборки объявлены в его
`pom.xml`, а доступ между Java-модулями — в `module-info.java` (JPMS).

Компилятор запрещает импорт из модуля без соответствующего `requires` и
доступ к пакету без `exports`. Сейчас пакетов и экспортов нет: открывать
будем только необходимые контракты по мере их появления. Не используем
`open module`, `--add-reads` или `--add-exports` для обхода ограничений.

Правила защищают сборку от случайных импортов. Разработчик всё ещё может
изменить сами дескрипторы: изменения зависимостей требуют такого же ревью,
как изменения бизнес-логики. JPMS не запрещает файловые операции из
`java.base` внутри домена; это отдельное архитектурное правило.

Внешние библиотеки для DI и DDD-инфраструктура не нужны.

## Сборка

Требуются JDK 17+ и Maven 3.9+:

```sh
mvn verify
```

Выполнять из корня проекта. Корневой Maven-проект собирает модули в порядке
их зависимостей. Пока сборка проверяет только каркас; запускаемого приложения
и тестов бизнес-логики ещё нет.
